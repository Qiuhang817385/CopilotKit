title: "步骤 3：Copilot 可读状态"
---

此时，我们的应用中有一个聊天弹出窗口，我们可以直接与助手聊天。这很棒，但我们的助手对我们的应用一无所知。在这一步中，我们将为助手提供待办事项的状态。

在这一步中，您将学习如何向助手提供知识。在我们的例子中，我们希望助手了解应用中的任务。

## 我们应用的状态

让我们快速回顾一下我们应用的状态是如何工作的。打开 [`lib/hooks/use-tasks.tsx`](https://github.com/CopilotKit/example-todos-app/blob/base-start-here/lib/hooks/use-tasks.tsx) 文件。

一眼看去，我们可以看到该文件暴露了一个提供者（`TasksProvider`），它定义了一些有用的东西：

- 我们任务的状态（`tasks`）
- 添加任务的函数（`addTask`）
- 更新任务的函数（`updateTask`）
- 删除任务的函数（`deleteTask`）

所有这些都是通过一个 `useTasks` Hook 消费的，我们在应用的其他部分使用它（可以随意查看 `TasksList`、`AddTask` 和 `Task` 组件）。

这类似于大多数 React 应用，其中功能或整个应用的前端状态由上下文或状态管理库管理。

## `useCopilotReadable` Hook

我们的目标是让我们的助手了解这个状态，以便它能够提供更准确和有用的回复。我们可以使用 [`useCopilotReadable`](/reference/v1/hooks/useCopilotReadable) Hook 轻松实现这一点。

```tsx title="lib/hooks/use-tasks.tsx" {3,8-11}
// ... 文件的其余部分

import { useCopilotReadable } from "@copilotkit/react-core/v2"; // [!code highlight]

export const TasksProvider = ({ children }: { children: ReactNode }) => {
  const [tasks, setTasks] = useState<Task[]>(defaultTasks);

  // [!code highlight:4]
  useCopilotReadable({
    description: "The state of the todo list",
    value: JSON.stringify(tasks)
  });

  // ... 文件的其余部分
}
```

在这个例子中，我们使用 `useCopilotReadable` Hook 向助手提供任务的状态。

- 对于 `description` 属性，我们提供了一个简洁的描述，告诉助手这段可读数据的含义。
- 对于 `value` 属性，我们将整个状态作为 JSON 字符串传递。
