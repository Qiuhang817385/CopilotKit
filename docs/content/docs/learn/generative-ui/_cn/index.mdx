## 什么是生成式 UI？

<TwoColumnSection
  imagePosition="right"
  imageSrc="/images/generative-ui/generative-ui-light.png"
  imageSrcDark="/images/generative-ui/generative-ui-dark.png"
  imageAlt="生成式 UI 概述图"
  imageWidth={600}
  imageHeight={400}
>

生成式 UI 指的是**部分或完全由 AI 智能体生成**的用户界面，而不是仅由人类设计师和开发人员编写。UI 不是预先手工制作的，智能体在决定屏幕上显示什么、信息如何结构化，甚至在某些情况下布局如何组合方面发挥作用。

核心思想很简单：随着智能体变得更加强大，智能体应用程序的 UI 本身变得更加动态——能够适应、重组和响应用户意图和应用程序上下文。这可以通过非常不同的方式完成，每种方式都有自己的权衡。

本页面涵盖：

- **[应用程序表面](#生成式-ui-的应用程序表面)** - 生成式 UI 在智能体应用程序中出现的位置。
- **[属性](#生成式-ui-的属性)** - 不同的生成式 UI 类型和用途如何变化及其原因。
- **[类型](#生成式-ui-的类型)** - 主要的生成式 UI 类型、它们的用途和权衡。
- **[生态系统映射](#生态系统映射)** - 不同类型的生成式 UI 如何在生态系统中使用。
- **[AG-UI 和 CopilotKit](#ag-ui-和-copilotkit-是生成式-ui-无关的)** - AG-UI 和 CopilotKit 如何与不同类型的生成式 UI 协同工作。

</TwoColumnSection>

## 生成式 UI 的应用程序表面

生成式 UI 可以根据用户如何与智能体交互以及应用程序如何调解该交互而在应用程序的不同部分出现。这些表面决定了用户体验、开发人员职责以及生成式 UI 出现的位置。

### 1. 聊天（线程交互）

<TwoColumnSection
  imagePosition="right"
  imageSrc="/images/generative-ui/chat-surface.png"
  imageAlt="聊天表面 - 线程交互"
  imageWidth={300}
  imageHeight={200}
>

类似 Slack 的对话界面，应用程序协调每次交互。生成式 UI 以内联方式显示为卡片、块或工具响应。

**主要特征：**
- 基于轮次、消息驱动的流程。
- 应用程序协调所有智能体通信。
- 非常适合支持、问答、调试和引导式工作流。

**示例：** Slack 机器人、Discord 机器人、Intercom AI 智能体、Zendesk AI、GitHub Copilot Chat、Notion AI Chat。

</TwoColumnSection>

### 2. 聊天+（协作者工作区）

<TwoColumnSection
  imagePosition="left"
  imageSrc="/images/generative-ui/chat-plus-surface.png"
  imageAlt="聊天+ 表面 - 协作者工作区"
  imageWidth={600}
  imageHeight={400}
>

并排或多窗格布局：一个窗格中有聊天，另一个窗格中有动态画布。画布成为一个共享工作空间，智能体生成的 UI 在其中出现和演变。

**主要特征：**
- 聊天保持存在但次要。
- 画布显示结构化输出和预览。
- 生成式 UI 可以出现在画布或聊天空间中。
- 非常适合创建、规划、编辑和多步骤任务。

**示例：** Figma AI、Notion AI 工作区、Google Workspace Duet 侧面板、Replit Ghostwriter 配对编辑器。

</TwoColumnSection>

### 3. 无聊天（生成式 UI 集成到应用程序 UI 中）

<TwoColumnSection
  imagePosition="right"
  imageSrc="/images/generative-ui/chatless-surface.png"
  imageAlt="无聊天表面 - 集成的应用程序 UI"
  imageWidth={300}
  imageHeight={200}
>

智能体不直接与用户对话。相反，它通过 API 与应用程序通信，应用程序将智能体的生成式 UI 渲染为其原生界面的一部分。

**主要特征：**
- 根本没有聊天表面。
- 应用程序决定生成式 UI 何时何地出现。
- 感觉像内置的产品功能，而不是对话。
- 非常适合仪表板、建议和自主任务助手。

**示例：** Microsoft 365 Copilot（内联编辑）、Linear Insights、Superhuman AI 分类、HubSpot AI Assist、Datadog Notebooks AI 面板。

</TwoColumnSection>

生成式 UI 的类型，甚至单个用途在两个属性方面差异很大：自由度和控制。

### 开放式生成式 UI

<PatternCard
  id="open-ended"
  index={2}
  title="开放式"
  subtitle="智能体返回任意 UI（HTML、iframe、自由格式内容）"
  description="开放式生成式 UI 代表了光谱的另一端。在这里，智能体生成完整的 UI 表面——通常以 HTML、iframe 或自由格式标记的形式。智能体不是从预定义组件中选择，而是可以用整个 UI 负载响应，前端只需显示它。"
  fullDescription="这种方法提供了无与伦比的表达灵活性。智能体可以渲染日历、自定义表格、动画可视化或交互式 HTML 小部件，无论是由 LLM 生成还是由应用程序开发人员预定义。"
  whyUse={[

### 声明式生成式 UI

<PatternCard
  id="declarative"
  index={3}
  title="声明式"
  subtitle="智能体返回结构化的 UI 规范（卡片、列表、表单、小部件）"
  description="声明式生成式 UI 通过让智能体返回结构化规范而不是任意 UI 代码来平衡结构和灵活性。智能体不是自由格式的 HTML，而是发出明确定义的模式——例如由声明式标准定义的卡片、列表、表单或小部件集合。"
  fullDescription="这种方法在保持一致性的同时，给予智能体比纯静态组件库更大的表达能力。它创造了一个中间地带，UI 不是为每个用例手工制作的，但也不是完全自由格式的。"
  whyUse={[
    "支持广泛的用例，无需为每个用例自定义组件。",
    "开发人员可以在多个框架（React、移动端、桌面端等）中渲染相同的规范。",

  ]}

    "可能无法实现自定义 UI 模式。",

## AG-UI 和 CopilotKit 是生成式 UI 无关的

      **AG-UI 旨在支持全谱系的生成式 UI 技术**，同时添加统一它们的重要能力。

      AG-UI 与所有类型无缝集成：静态、声明式和开放式生成式 UI 方法。无论团队更喜欢手工制作的组件、结构化模式还是智能体编写的表面，AG-UI 都可以支持该工作流。
