CopilotKit 提供全面的错误处理能力，帮助您调试问题并监控应用程序的行为。无论您是在本地开发还是在生产环境中运行，CopilotKit 都提供工具来有效捕获、理解和解决错误。

## 快速开始

<Steps>

<Step>
### 使用开发控制台进行本地开发

对于本地开发，启用开发控制台以直接在 UI 中查看错误：

```tsx
import { CopilotKit } from "@copilotkit/react-core";

export default function App() {
  return (
    <CopilotKit
      runtimeUrl="<your-runtime-url>"
      showDevConsole={true} // [!code highlight]
    >
      {/* 您的应用 */}
    </CopilotKit>
  );
}
```

<Callout type="tip">
  开发控制台直接在您的 UI 中显示错误横幅，使在开发过程中发现问题变得容易。**此功能不需要 API 密钥**。
</Callout>

</Step>

<Step>
### 生产环境错误可观察性

对于生产应用程序，使用错误可观察性钩子将错误发送到监控服务（需要 `publicApiKey`）：

```tsx
import { CopilotKit } from "@copilotkit/react-core";

export default function App() {
  return (
    <CopilotKit
      runtimeUrl="<your-runtime-url>"
      publicApiKey="ck_pub_your_key" // [!code highlight]
      onError={(errorEvent) => {
        // [!code highlight]
        // 发送到您的监控服务
        console.error("CopilotKit 错误:", errorEvent);

        // 示例：发送到分析
        analytics.track("copilotkit_error", {
          type: errorEvent.type,
          source: errorEvent.context.source,
          timestamp: errorEvent.timestamp,
        });
      }} // [!code highlight]
      showDevConsole={false} // 在生产环境中隐藏开发控制台
    >
      {/* 您的应用 */}
    </CopilotKit>
  );
}
```

<Callout type="info">
  **需要 publicApiKey？** 前往
  [https://cloud.copilotkit.ai](https://cloud.copilotkit.ai) 免费获取一个！
</Callout>

</Step>

</Steps>

## 错误处理选项

### 开发控制台 (`showDevConsole`)

开发控制台在开发过程中提供即时的视觉反馈：

```tsx
<CopilotKit runtimeUrl="<your-runtime-url>" showDevConsole={true}>
  {/* 您的应用 */}
</CopilotKit>
```

**功能：**

- ✅ **无需 API 密钥** - 适用于任何设置
- ✅ **视觉错误横幅** - 错误以横幅形式出现在您的 UI 中
- ✅ **实时反馈** - 错误发生时立即查看
- ✅ **面向开发** - 详细的错误信息用于调试

**最适合：**

- 本地开发
- 测试和调试
- 理解错误流程

<Callout type="warn">
  在生产环境中设置 `showDevConsole={false}` 以避免向最终用户显示错误详细信息。
</Callout>

### 错误可观察性 (`onError`)

错误可观察性钩子提供对详细错误信息的编程访问，用于监控和分析：

```tsx
import { CopilotErrorEvent } from "@copilotkit/shared";

<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent: CopilotErrorEvent) => {
    // 将错误数据发送到监控服务
    switch (errorEvent.type) {
      case "error":
        logToService("关键错误", errorEvent);
        break;
      case "request":
        logToService("请求开始", errorEvent);
        break;
      case "response":
        logToService("收到响应", errorEvent);
        break;
      case "agent_state":
        logToService("智能体状态变化", errorEvent);
        break;
    }
  }}
>
  {/* 您的应用 */}
</CopilotKit>;
```

**功能：**

- ✅ **丰富的错误上下文** - 关于出错内容的详细信息
- ✅ **请求/响应跟踪** - 监控完整的对话流程
- ✅ **智能体状态监控** - 跟踪智能体交互和状态变化
- ✅ **生产就绪** - 适合监控服务的结构化数据

**要求：**

- 需要从 [Copilot Cloud](https://cloud.copilotkit.ai) 获取 `publicApiKey`
- CopilotKit 企业可观察性产品的一部分

<Callout type="info">
  **注意：** 基本错误处理无需 Cloud 即可工作。`onError` 钩子专门用于 **错误可观察性** - 将错误数据发送到 Sentry、DataDog 等监控服务。
</Callout>

## 错误事件结构

`onError` 处理器接收带有丰富上下文的详细错误事件：

```typescript
interface CopilotErrorEvent {
  type:
    | "error"
    | "request"
    | "response"
    | "agent_state"
    | "action"
    | "message"
    | "performance";
  timestamp: number;
  context: {
    source: "ui" | "runtime" | "agent";
    request?: {
      operation: string;
      method?: string;
      url?: string;
      startTime: number;
    };
    response?: {
      endTime: number;
      latency: number;
    };
    agent?: {
      name: string;
      nodeName?: string;
    };
    messages?: {
      input: any[];
      messageCount: number;
    };
    technical?: {
      environment: string;
      stackTrace?: string;
    };
  };
  error?: any; // 错误事件时存在
}
```

## 常见错误可观察性模式

### 基本错误日志记录

```tsx
<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent) => {
    console.error("[CopilotKit 错误]", {
      type: errorEvent.type,
      timestamp: new Date(errorEvent.timestamp).toISOString(),
      context: errorEvent.context,
      error: errorEvent.error,
    });
  }}
>
  {/* 您的应用 */}
</CopilotKit>
```

### 与监控服务集成

```tsx
// Sentry 示例
import * as Sentry from "@sentry/react";

<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent) => {
    if (errorEvent.type === "error") {
      Sentry.captureException(errorEvent.error, {
        tags: {
          source: errorEvent.context.source,
          operation: errorEvent.context.request?.operation,
        },
        extra: {
          context: errorEvent.context,
          timestamp: errorEvent.timestamp,
        },
      });
    }
  }}
>
  {/* 您的应用 */}
</CopilotKit>;
```

### 自定义错误分析

```tsx
<CopilotKit
  publicApiKey="ck_pub_your_key"
  onError={(errorEvent) => {
    // 跟踪不同的错误类型
    analytics.track("copilotkit_event", {
      event_type: errorEvent.type,
      source: errorEvent.context.source,
      agent_name: errorEvent.context.agent?.name,
      latency: errorEvent.context.response?.latency,
      error_message: errorEvent.error?.message,
      timestamp: errorEvent.timestamp,
    });
  }}
>
  {/* 您的应用 */}
</CopilotKit>
```

## 开发与生产设置

### 开发环境

```tsx
<CopilotKit
  runtimeUrl="http://localhost:3000/api/copilotkit"
  showDevConsole={true} // 显示视觉错误
  onError={(errorEvent) => {
    // 开发环境的简单控制台日志
    console.log("CopilotKit 事件:", errorEvent);
  }}
>
  {/* 您的应用 */}
</CopilotKit>
```

### 生产环境

```tsx
<CopilotKit
  runtimeUrl="https://your-app.com/api/copilotkit"
  publicApiKey={process.env.NEXT_PUBLIC_COPILOTKIT_API_KEY}
  showDevConsole={false} // 对用户隐藏
  onError={(errorEvent) => {
    // 生产环境错误可观察性
    if (errorEvent.type === "error") {
      // 记录关键错误
      logger.error("CopilotKit 错误", {
        error: errorEvent.error,
        context: errorEvent.context,
        timestamp: errorEvent.timestamp,
      });

      // 发送到监控服务
      monitoring.captureError(errorEvent.error, {
        extra: errorEvent.context,
      });
    }
  }}
>
  {/* 您的应用 */}
</CopilotKit>
```

## 最佳实践

### ✅ 应该做

- **在开发期间使用 `showDevConsole={true}`** 以获得即时反馈
- **在生产环境中设置 `showDevConsole={false}`** 以向用户隐藏错误
- **使用 `onError` 钩子实施适当的错误可观察性** 进行监控
- **监控错误模式** 以主动识别和修复问题
- **使用结构化日志记录** 使错误分析更容易

### ❌ 不应该做

- **不要在生产环境中向最终用户暴露详细错误**
- **不要忽略错误事件** - 它们提供有价值的调试信息
- **不要在错误可观察性钩子中记录敏感数据**
- **不要用错误处理逻辑阻塞 UI**

## 故障排除

### 错误可观察性不起作用

如果您的 `onError` 钩子没有被调用：

1. **检查您的 publicApiKey** - 错误可观察性需要有效的 API 密钥
2. **验证密钥格式** - 应以 `ck_pub_` 开头
3. **确保密钥已设置** - 检查您的环境变量
4. **使用开发控制台测试** - 使用 `showDevConsole={true}` 查看错误是否正在发生

### 开发控制台不显示

如果开发控制台没有显示错误：

1. **检查 showDevConsole 设置** - 确保它设置为 `true`
2. **查看控制台错误** - 检查浏览器开发工具中的 JavaScript 错误
3. **验证错误发生** - 确保错误确实正在发生
