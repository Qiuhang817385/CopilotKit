## 我的工具调用没有被流式传输

这可能是由于几个不同的原因造成的。

首先，我们强烈建议您查看我们的 [Human In the Loop](/langgraph/human-in-the-loop) 指南，了解如何在 LangGraph Agent 中流式传输工具调用的更深入示例。您还可以查看我们的 [旅行教程](/langgraph/tutorials/ai-travel-app/step-6-human-in-the-loop)，该教程讨论了如何在更复杂的示例中流式传输工具调用。

如果您已经完成了这些步骤，可以检查以下内容：

<Accordions>
    <Accordion title="您使用的是 llm.invoke() 而不是 llm.ainvoke()">
        <p>
            当您调用 LangGraph Agent 时，可以同步或异步调用。如果您同步调用，工具调用将不会逐步流式传输，只会流式传输最终结果。如果您异步调用，工具调用将逐步流式传输。

            ```python
            config = copilotkit_customize_config(config, emit_tool_calls=["say_hello_to"])
            response = await llm_with_tools.ainvoke(
                [ SystemMessage(content=system_message), *state["messages"] ],
                config=config
            )
            ```
        </p>
    </Accordion>

</Accordions>

## 错误：`'AzureOpenAI' object has no attribute 'bind_tools'`

此错误通常是由于从 LangGraph 使用了错误的导入。不要将 `AzureOpenAI` 导入，而是导入 `AzureChatOpenAI`，您的问题就会解决。

```python
from langchain_openai import AzureOpenAI # [!code --]
from langchain_openai import AzureChatOpenAI # [!code ++]
```

## 我收到 "agent not found" 错误

如果您看到此错误，这意味着 CopilotKit 找不到您尝试使用的 LangGraph Agent。以下是修复方法：

<Accordions>
    <Accordion title="验证您的 Agent 锁定模式配置">
        如果您使用 Agent 锁定模式，请检查 `langgraph.json` 中定义的 Agent 是否与 CopilotKit 提供程序中定义的一致：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// 在本例中，"my_agent" 是您正在使用的 Agent // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```tsx title="layout.tsx"
        {/* [!code highlight:1] */}
        <CopilotKit agent="my_agent">
            {/* 您的应用程序组件 */}
        </CopilotKit>
        ```

        常见问题：
        - Agent 名称拼写错误
        - 大小写不匹配
        - `langgraph.json` 中缺少条目
    </Accordion>
    <Accordion title="检查您在 LangGraph Platform 端点上的 Agent 注册">
        使用 LangGraph Platform 端点时，请确保您的 Agent 已正确定义并遵循 `langgraph.json` 中的定义：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// 在本例中，"my_agent" 是您正在使用的 Agent // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```typescript title="/copilotkit/api/route.ts"
        const runtime = new CopilotRuntime({
          // ... CopilotRuntime 定义的其余部分
          // [!code highlight:7]
          agents: {
            'my_agent': new LangGraphAgent({
              deploymentUrl: '<your-api-url>',
              graphId: 'my_agent',
              langsmithApiKey: '<your-langsmith-api-key>' // 可选
            }),
          },
        });
        ```
    </Accordion>
    <Accordion title="检查您在 useCoAgent 中的 Agent 名称">
        确保 `langgraph.json` 中定义的 Agent 与您在 `useCoAgent` Hook 中使用的一致：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// 在本例中，"my_agent" 是您正在使用的 Agent // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```tsx title="MyComponent.tsx"
        // 您的 React 组件
        useAgent({
            agentId: "my_agent", // [!code focus]
        });
        ```
    </Accordion>
    <Accordion title="检查您在 useCoAgentStateRender 中的 Agent 名称">
        确保 `langgraph.json` 中定义的 Agent 与您在 `useAgent` Hook 中使用的一致：

        ```json title="langgraph.json"
        {
            "python_version": "3.12",
            "dockerfile_lines": [],
            "dependencies": ["."],
            "graphs": {
                "my_agent": "./src/agent.py:graph"// 在本例中，"my_agent" 是您正在使用的 Agent // [!code highlight]
            },
            "env": ".env"
        }
        ```

        ```tsx title="MyComponent.tsx"
        // 您的 React 组件
        useCoAgentStateRender({
            name: "my_agent", // [!code focus] 这必须完全匹配
        });
        ```
    </Accordion>

</Accordions>

## 隧道创建的连接问题

如果您注意到隧道创建过程无限旋转，您的路由器或 ISP 可能会阻止与 CopilotKit 隧道服务的连接。

<Accordions>
    <Accordion title="路由器或 ISP 阻止隧道连接">
        要验证与隧道服务的连接，请尝试以下命令：

        ```bash
        ping tunnels.devcopilotkit.com
        curl -I https://tunnels.devcopilotkit.com
        telnet tunnels.devcopilotkit.com 443
        ```

        如果这些命令失败，您的路由器安全功能或 ISP 可能会阻止连接。常见解决方案：
        - 检查路由器安全设置
        - 考虑咨询您的 ISP 有关任何连接限制
        - 尝试使用移动热点
    </Accordion>

</Accordions>

## 我收到 "Failed to find or contact remote endpoint at url, Make sure the API is running and that it's indeed a LangGraph platform url" 错误

如果您看到此错误，这意味着 LangGraph Platform 客户端无法连接到您的端点。

<Accordions>
    <Accordion title="验证端点是否可访问">
        检查在远程端点 URL 上运行的后端 API 的日志。确保它已启动并准备好接收请求
    </Accordion>
    <Accordion title="验证使用 LangGraph 部署工具运行 LangGraph Platform 端点">
        验证后端 API 是否使用 `langgraph dev`、`langgraph up`、LangGraph 云 URL 或 LangGraph 提供的等效方法运行
    </Accordion>
    <Accordion title="验证远程端点是否与端点定义类型匹配">
        如果您使用 FastAPI 运行远程端点，即使它使用 LangGraph 作为 Agent，也不被视为 LangGraph Platform 端点。
        您可能需要更改此端点的 `remoteEndpoints` 定义以匹配预期格式。

        更改端点定义，从：
        ```
        new CopilotRuntime({
          remoteEndpoints: [
            langGraphPlatformEndpoint({
            deploymentUrl: "https://your-fastapi-endpoint:port",
            langsmithApiKey: '<langsmith API key>' // 可选
            agents: [], // 您之前的 Agent 定义
          ],
        });

        // 或

        new CopilotRuntime({
          agents: {
            'agent-name': new LangGraphAgent({
              deploymentUrl: "https://your-fastapi-endpoint:port",
              langsmithApiKey: '<langsmith API key>', // 可选
              graphId: 'langgraph.json graph id', // 您之前的 graphId 定义
            }),
          }
        });
        ```

        到：
        ```
        new CopilotRuntime({
            agents: {
                'agent-name': new LangGraphHttpAgent({
                    url: 'https://your-fastapi-endpoint:port/your-agent-uri'
                }),
            }
        });
        ```
    </Accordion>
</Accordions>

## 将 LangGraph 与 FastAPI 一起使用时出现 "No checkpointer set" 错误

如果您遇到此错误，这意味着您编译的图中缺少检查点器。
您可以访问 [LangGraph Persistence 指南](https://docs.langchain.com/oss/python/langgraph/persistence#checkpoints) 了解什么是检查点器以及如何添加它。

## 我看到消息被流式传输然后消失

LangGraph Agent 是有状态的。随着图的遍历，状态会在每个节点结束时保存。CopilotKit 使用 Agent 的状态作为前端聊天中显示内容的真相来源。然而，由于状态仅在节点结束时发出，CopilotKit 允许您流式传输预测状态更新*在节点中间*。默认情况下，CopilotKit 会将正在主动生成的消息和工具调用流式传输到发起交互的前端聊天。**如果此预测状态在节点结束时没有持久化，它将在前端聊天中消失**。

在这种情况下，最可能的情况是在节点中间更新了状态中的 `messages` 属性，但这些编辑在节点结束时没有被持久化。

<img src="https://cdn.copilotkit.ai/docs/copilotkit/images/coagents/message-state-diagram.png" />

<Accordions>
    <Accordion title="我希望这些消息被持久化">
        要修复此问题，您可以简单地在节点结束时返回新消息来持久化消息。

         <Tabs groupId="language_langgraph_agent" items={["Python", "TypeScript"]} persist>
            <Tab value="Python">
                ```python
                from copilotkit.langgraph import copilotkit_customize_config

                async def chat_node(state: AgentState, config: RunnableConfig):
                    # 1) 使用 CopilotKit 修改后的配置调用模型
                    model = ChatOpenAI(model="gpt-5.2")
                    response = await model.ainvoke(state["messages"], modifiedConfig)

                    # 2) 确保返回新消息
                    return {
                        messages: response,
                    }
                ```
            </Tab>
            <Tab value="TypeScript">
                ```typescript
                import { copilotkitCustomizeConfig } from '@copilotkit/sdk-js/langgraph';

                async function chatNode(state: AgentState, config: RunnableConfig): Promise<AgentState> {
                    // 1) 使用 CopilotKit 修改后的配置调用模型
                    const model = new ChatOpenAI({ temperature: 0, model: "gpt-5.2" });
                    const response = await model.invoke(state.messages, modifiedConfig);

                    # 2) 确保返回新消息
                    return {
                        messages: response,
                    }
                }
                ```
            </Tab>
        </Tabs>
    </Accordion>
    <Accordion title="我根本不想流式传输这些消息">
        在这种情况下，您可以参考我们关于 [禁用流式传输](/langgraph/advanced/disabling-state-streaming) 的文档。更具体地说，您可以使用 copilotkit 配置来禁用任何您不想流式传输消息的地方的消息发出。

        <Tabs groupId="language_langgraph_agent" items={["Python", "TypeScript"]} persist>
            <Tab value="Python">
                ```python
                from copilotkit.langgraph import copilotkit_customize_config

                async def chat_node(state: AgentState, config: RunnableConfig):
                    # 1) 配置 CopilotKit 不发出消息
                    modifiedConfig = copilotkit_customize_config(
                        config,
                        emit_messages=False, # 如果您想禁用消息流式传输
                    )

                    # 2) 使用 CopilotKit 修改后的配置调用模型
                    model = ChatOpenAI(model="gpt-5.2")
                    response = await model.ainvoke(state["messages"], modifiedConfig)

                    # 3) 不要返回新响应以向用户隐藏它
                    return state
                ```
            </Tab>
            <Tab value="TypeScript">
                ```typescript
                import { copilotkitCustomizeConfig } from '@copilotkit/sdk-js/langgraph';

                async function chatNode(state: AgentState, config: RunnableConfig): Promise<AgentState> {
                    // 1) 配置 CopilotKit 不发出消息
                    const modifiedConfig = copilotkitCustomizeConfig(config, {
                        emitMessages: false, // 如果您想禁用消息流式传输
                    });

                    // 2) 使用 CopilotKit 修改后的配置调用模型
                    const model = new ChatOpenAI({ temperature: 0, model: "gpt-5.2" });
                    const response = await model.invoke(state.messages, modifiedConfig);

                    // 3) 不要返回新响应以向用户隐藏它
                    return state;
                }
                ```
            </Tab>
        </Tabs>

        <Callout title="运行子图或 langchain？">
            只需确保将上面定义的修改后的配置作为子图或 langchain 的 `RunnableConfig` 传递即可！
        </Callout>
    </Accordion>
</Accordions>
