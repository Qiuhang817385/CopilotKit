CopilotKit 构建于 [AG-UI 协议](https://ag-ui.com) 之上 —— 这是一种轻量级、基于事件的标准，定义了 AI 智能体如何通过服务器发送事件（SSE）与用户应用程序通信。

CopilotKit 中的所有内容 —— 消息、状态更新、工具调用等 —— 都通过 AG-UI 事件流动。理解这一层有助于您更有效地调试、扩展和构建 CopilotKit。

## 使用 `useAgent` 访问您的智能体

`useAgent` 钩子是您与驱动协驾驶舱的 AG-UI 智能体交互的主要接口。它从 AG-UI 客户端库返回一个 [`AbstractAgent`](https://github.com/ag-ui-protocol/ag-ui/blob/main/typescript/packages/client/src/agents/abstract-agent.ts) —— 所有 AG-UI 智能体都实现的相同基类型。

```tsx
import { useAgent } from "@copilotkit/react-core";

function MyComponent() {
  const { agent } = useAgent();

  // agent.messages - 对话历史
  // agent.state - 当前智能体状态
  // agent.isRunning - 智能体是否正在运行
}
```

如果您有多个智能体，请传递 `agentId` 来选择其中一个：

```tsx
const { agent } = useAgent({ agentId: "research-agent" });
```

返回的 `agent` 是一个标准的 AG-UI `AbstractAgent`。您可以订阅它的事件、读取其状态，并使用 [AG-UI 规范](https://docs.ag-ui.com) 定义的相同接口与其交互。

### 订阅 AG-UI 事件

每个智能体都暴露一个 `subscribe` 方法，让您可以在事件流式传入时监听特定的 AG-UI 事件。每个回调接收事件和当前智能体状态：

```tsx
import { useAgent } from "@copilotkit/react-core";
import { useEffect } from "react";

function MyComponent() {
  const { agent } = useAgent();

  useEffect(() => {
    const subscription = agent.subscribe({
      // 每个事件触发
      onEvent({ event, agent }) {
        console.log("事件:", event.type, event);
      },

      // 文本消息流式传输
      onTextMessageContentEvent({ event, textMessageBuffer, agent }) {
        console.log("流式文本:", textMessageBuffer);
      },

      // 工具调用
      onToolCallEndEvent({ event, toolCallName, toolCallArgs, agent }) {
        console.log("工具调用:", toolCallName, toolCallArgs);
      },

      // 状态更新
      onStateSnapshotEvent({ event, agent }) {
        console.log("状态快照:", agent.state);
      },

      // 高级生命周期
      onMessagesChanged({ agent }) {
        console.log("消息已更新:", agent.messages);
      },
      onStateChanged({ agent }) {
        console.log("状态已改变:", agent.state);
      },
    });

    return () => subscription.unsubscribe();
  }, [agent]);
}
```

可订阅事件的完整列表直接映射到 [AG-UI 事件类型](https://docs.ag-ui.com/concepts/events)：

| 事件 | 回调 | 描述 |
| --- | --- | --- |
| 运行生命周期 | `onRunStartedEvent`, `onRunFinishedEvent`, `onRunErrorEvent` | 智能体运行开始、完成和错误 |
| 步骤 | `onStepStartedEvent`, `onStepFinishedEvent` | 运行中单个步骤的边界 |
| 文本消息 | `onTextMessageStartEvent`, `onTextMessageContentEvent`, `onTextMessageEndEvent` | 来自智能体的流式文本内容 |
| 工具调用 | `onToolCallStartEvent`, `onToolCallArgsEvent`, `onToolCallEndEvent`, `onToolCallResultEvent` | 工具调用生命周期 |
| 状态 | `onStateSnapshotEvent`, `onStateDeltaEvent` | 完整状态快照和增量更新 |
| 消息 | `onMessagesSnapshotEvent` | 完整消息列表快照 |
| 自定义 | `onCustomEvent`, `onRawEvent` | 用于扩展性的自定义和原始事件 |
| 高级 | `onMessagesChanged`, `onStateChanged` | 任何消息或状态变更后的聚合通知 |

## 代理模式

当您使用 CopilotKit 与运行时配合时，您的前端从不直接与智能体通信。相反，CopilotKit 在前端创建一个**代理智能体**，通过 Copilot Runtime 转发请求。

启动时，CopilotKit 调用运行时的 `/info` 端点来发现可用的智能体。每个智能体都被包装在一个 `ProxiedCopilotRuntimeAgent` 中 —— 一个继承自 AG-UI 的 [`HttpAgent`](https://github.com/ag-ui-protocol/ag-ui/blob/main/typescript/packages/client/src/agents/http-agent.ts) 的瘦客户端。从组件的角度来看，这个代理的行为与本地 AG-UI 智能体完全相同：相同的 `AbstractAgent` 接口、相同的订阅 API、相同的属性。但在底层，每个 `run` 调用都是向服务器的 HTTP 请求，每个响应都是流回前端代理的 AG-UI 事件 SSE 流。

```tsx title="您的组件看到的"
const { agent } = useAgent(); // 返回 AbstractAgent
agent.messages;               // 读取消息
agent.state;                  // 读取状态
agent.subscribe({ ... });     // 订阅事件
```

```tsx title="实际发生的事情"
// useAgent() → AgentRegistry 检查 /info → 将每个智能体包装在 ProxiedCopilotRuntimeAgent 中
// agent.runAgent() → HTTP POST 到运行时 → 运行时路由到您的智能体 → SSE 流返回
```

这种间接性使得运行时能够提供身份验证、中间件、智能体路由和生态系统功能，如 [线程](/premium/threads) 和 [可观测性](/premium/observability) —— 而无需改变您在前端与智能体交互的方式。

## 智能体如何融入运行时

在服务器端，`CopilotRuntime` 接受一个 AG-UI `AbstractAgent` 实例的映射。每个智能体框架都提供自己的实现，但它们都继承自相同的基类型：

```ts title="app/api/copilotkit/route.ts"
import { CopilotRuntime, copilotRuntimeNextJSAppRouterEndpoint } from "@copilotkit/runtime";
import { HttpAgent } from "@ag-ui/client";

const runtime = new CopilotRuntime({
  agents: {
    "my-agent": new HttpAgent({
      url: "https://my-agent-server.example.com",
    }),
  },
});

export const POST = async (req: NextRequest) => {
  const { handleRequest } = copilotRuntimeNextJSAppRouterEndpoint({
    runtime,
    endpoint: "/api/copilotkit",
  });
  return handleRequest(req);
};
```

当请求到达时：

1. 运行时通过 ID 解析目标智能体
2. 它克隆智能体（为了线程安全）并从请求中设置消息、状态和线程上下文
3. `AgentRunner` 执行智能体，产生一个 AG-UI `BaseEvent` 流
4. 事件被编码为 SSE 并流式传输回前端代理

因为每个智能体都是 `AbstractAgent`，您可以注册任何 AG-UI 兼容的智能体 —— 无论是指向远程服务器的 `HttpAgent`、框架特定的适配器，还是自定义实现 —— 运行时都会统一处理路由、中间件和交付。
