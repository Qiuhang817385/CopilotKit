CopilotKit 基于 [AG-UI 协议](https://ag-ui.com) 构建——一个轻量级、基于事件的标准，定义了 AI 代理如何通过服务器发送事件 (SSE) 与用户应用程序通信。

CopilotKit 中的所有内容——消息、状态更新、工具调用等——都通过 AG-UI 事件流动。了解这一层有助于您更有效地调试、扩展和构建 CopilotKit。

## 使用 `useAgent` 访问您的代理

`useAgent` 钩子是您访问为助手提供支持的 AG-UI 代理的主要接口。它从 AG-UI 客户端库返回一个 [`AbstractAgent`](https://github.com/ag-ui-protocol/ag-ui/blob/main/typescript/packages/client/src/agents/abstract-agent.ts)——所有 AG-UI 代理实现的基本类型。

```tsx
import { useAgent } from "@copilotkit/react-core";

function MyComponent() {
  const { agent } = useAgent();

  // agent.messages - 对话历史
  // agent.state - 当前代理状态
  // agent.isRunning - 代理当前是否正在运行
}
```

如果您有多个代理，请传递 `agentId` 以选择其中一个：

```tsx
const { agent } = useAgent({ agentId: "research-agent" });
```

返回的 `agent` 是一个标准的 AG-UI `AbstractAgent`。您可以使用 [AG-UI 规范](https://docs.ag-ui.com) 定义的相同接口订阅其事件、读取其状态并与之交互。

### 订阅 AG-UI 事件

每个代理都公开一个 `subscribe` 方法，让您可以监听随着它们流式传输进来的特定 AG-UI 事件。每个回调接收事件和当前代理状态：

```tsx
import { useAgent } from "@copilotkit/react-core";
import { useEffect } from "react";

function MyComponent() {
  const { agent } = useAgent();

  useEffect(() => {
    const subscription = agent.subscribe({
      // 每个事件都会调用
      onEvent({ event, agent }) {
        console.log("事件:", event.type, event);
      },

      // 文本消息流式传输
      onTextMessageContentEvent({ event, textMessageBuffer, agent }) {
        console.log("流式传输文本:", textMessageBuffer);
      },

      // 工具调用
      onToolCallEndEvent({ event, toolCallName, toolCallArgs, agent }) {
        console.log("工具调用:", toolCallName, toolCallArgs);
      },

      // 状态更新
      onStateSnapshotEvent({ event, agent }) {
        console.log("状态快照:", agent.state);
      },

      // 高级生命周期
      onMessagesChanged({ agent }) {
        console.log("消息已更新:", agent.messages);
      },
      onStateChanged({ agent }) {
        console.log("状态已更改:", agent.state);
      },
    });

    return () => subscription.unsubscribe();
  }, [agent]);
}
```

可订阅事件的完整列表直接映射到 [AG-UI 事件类型](https://docs.ag-ui.com/concepts/events)：

| 事件 | 回调 | 描述 |
| --- | --- | --- |
| 运行生命周期 | `onRunStartedEvent`, `onRunFinishedEvent`, `onRunErrorEvent` | 代理运行开始、完成和错误 |
| 步骤 | `onStepStartedEvent`, `onStepFinishedEvent` | 运行中单个步骤的边界 |
| 文本消息 | `onTextMessageStartEvent`, `onTextMessageContentEvent`, `onTextMessageEndEvent` | 来自代理的流式文本内容 |
| 工具调用 | `onToolCallStartEvent`, `onToolCallArgsEvent`, `onToolCallEndEvent`, `onToolCallResultEvent` | 工具调用生命周期 |
| 状态 | `onStateSnapshotEvent`, `onStateDeltaEvent` | 完整状态快照和增量差异 |
| 消息 | `onMessagesSnapshotEvent` | 完整消息列表快照 |
| 自定义 | `onCustomEvent`, `onRawEvent` | 用于可扩展性的自定义和原始事件 |
| 高级 | `onMessagesChanged`, `onStateChanged` | 任何消息或状态变更后的聚合通知 |

## 代理模式

当您将 CopilotKit 与 Runtime 一起使用时，您的前端从不直接与您的代理对话。相反，CopilotKit 在前端创建一个**代理代理**，通过 Copilot Runtime 转发请求。

在启动时，CopilotKit 调用 Runtime 的 `/info` 端点以发现哪些代理可用。每个代理都包装在一个 `ProxiedCopilotRuntimeAgent` 中——一个扩展 AG-UI 的 [`HttpAgent`](https://github.com/ag-ui-protocol/ag-ui/blob/main/typescript/packages/client/src/agents/http-agent.ts) 的瘦客户端。从组件的角度来看，此代理的行为与本地 AG-UI 代理相同：相同的 `AbstractAgent` 接口，相同的订阅 API，相同的属性。但在底层，每个 `run` 调用都是对服务器的 HTTP 请求，每个响应都是流回前端的 AG-UI 事件的 SSE 流。

```tsx title="您的组件看到的内容"
const { agent } = useAgent(); // 返回一个 AbstractAgent
agent.messages;               // 读取消息
agent.state;                  // 读取状态
agent.subscribe({ ... });     // 订阅事件
```

```tsx title="实际发生的情况"
// useAgent() → AgentRegistry 检查 /info → 将每个代理包装在 ProxiedCopilotRuntimeAgent 中
// agent.runAgent() → HTTP POST 到 Runtime → Runtime 路由到您的代理 → SSE 流返回
```

这种间接性使 Runtime 能够提供身份验证、中间件、代理路由以及 [线程](/premium/threads) 和 [可观察性](/premium/observability) 等生态系统功能——而无需更改您在前端与代理交互的方式。

## 代理如何插入 Runtime

在服务器端，`CopilotRuntime` 接受 AG-UI `AbstractAgent` 实例的映射。每个代理框架都提供自己的实现，但它们都扩展了相同的基本类型：

```ts title="app/api/copilotkit/route.ts"
import { CopilotRuntime, copilotRuntimeNextJSAppRouterEndpoint } from "@copilotkit/runtime";
import { HttpAgent } from "@ag-ui/client";

const runtime = new CopilotRuntime({
  agents: {
    "my-agent": new HttpAgent({
      url: "https://my-agent-server.example.com",
    }),
  },
});

export const POST = async (req: NextRequest) => {
  const { handleRequest } = copilotRuntimeNextJSAppRouterEndpoint({
    runtime,
    endpoint: "/api/copilotkit",
  });
  return handleRequest(req);
};
```

当请求进来时：

1. Runtime 通过 ID 解析目标代理
2. 它克隆代理（为了线程安全）并从请求中设置消息、状态和线程上下文
3. `AgentRunner` 执行代理，产生 AG-UI `BaseEvent` 的流
4. 事件被编码为 SSE 并流回前端代理

因为每个代理都是 `AbstractAgent`，您可以注册任何 AG-UI 兼容的代理——无论是指向远程服务器的 `HttpAgent`、特定于框架的适配器还是自定义实现——Runtime 都会统一处理路由、中间件和交付。
